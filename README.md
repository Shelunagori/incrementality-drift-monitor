# incrementality-drift-monitor

**Incrementality evidence goes stale. This tells you when.**

> **All data in this repository is synthetic.** It is generated by
> `backend/scripts/generate_data.py`, with drift planted on purpose so the demo can show
> detection against a known truth. Nothing here comes from a real advertiser.

## Why

A marketing team runs an incrementality test on a channel (say Meta), gets a lift number, and
then trusts it for months. But the relationship between spend and sales drifts: creative
fatigues, competitors move, tracking changes. The old test quietly stops being true, and
nobody is told.

This tool keeps an **evidence ledger** per channel, watches daily spend and outcome data for
drift, and shows each channel as a traffic light:

| | Meaning |
|---|---|
| 🟢 GREEN | Recent evidence, and today's data agrees with it |
| 🟡 YELLOW | Evidence is old or missing, or a weak drift signal |
| 🔴 RED | Drift detected, or today's estimate contradicts the ledger |

An LLM agent then explains what changed in plain language and **proposes** a retest (geos,
duration, cost). A human approves before anything is executed.

### Principle: statistics decide, AI explains, human approves

- **Statistics decide** — changepoints (PELT), CUSUM, confidence intervals, power
  calculations and costs are deterministic Python (`backend/app/stats/`).
- **AI explains and proposes** — the agent only reads tool outputs. A guardrail rejects any
  answer containing a number that is not in the tool outputs it cites.
- **Human approves** — propose → approve → execute. Execution is idempotent and audited.

## Quick start

Requires Docker, [uv](https://docs.astral.sh/uv/) and Node 20+.

```bash
cp .env.example .env
make install     # backend + frontend dependencies
make demo        # Postgres, seed, backend :8000, frontend :3000, prints the story
```

Open http://localhost:3000. The walkthrough is in [docs/DEMO_SCRIPT.md](docs/DEMO_SCRIPT.md).

Other targets: `make dev`, `make seed`, `make test`, `make lint`, `make help`.

## LLM providers

Set in `.env`; the default is a local model via [Ollama](https://ollama.com).

| `LLM_PROVIDER` | Chat model setting | Key |
|---|---|---|
| `ollama` (default) | `OLLAMA_MODEL=llama3.1:8b` | – |
| `anthropic` | `ANTHROPIC_MODEL` | `ANTHROPIC_API_KEY` |
| `gemini` | `GEMINI_MODEL` | `GOOGLE_API_KEY` |
| `openai` | `OPENAI_MODEL` | `OPENAI_API_KEY` |
| `fake` | offline template writer (tests, no-model demos) | – |

`EMBEDDING_PROVIDER` takes the same values (`anthropic` uses Voyage AI with
`VOYAGE_API_KEY`, as Anthropic has no embeddings API). A missing key fails with a message
naming the variable. `make demo` falls back to `fake` if Ollama is not running.

## Tests

```bash
make test        # backend pytest (needs Postgres: `make db`) + frontend vitest
make lint        # ruff + eslint + tsc
```

The backend suite checks, among other things, that Meta turns RED within 30 days of the
planted drift, that stable channels never turn RED, that approval executes exactly once
(including under concurrent approvals), and that injected text in a ledger note cannot make
the agent draft a proposal. The LLM is replaced by deterministic fakes, so no model is needed.
CI (`.github/workflows/ci.yml`) runs both suites on every push.
